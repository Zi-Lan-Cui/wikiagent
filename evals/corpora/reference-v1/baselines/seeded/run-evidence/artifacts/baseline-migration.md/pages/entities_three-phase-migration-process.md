# 三阶段迁移流程

三阶段迁移流程是一种将数据库Schema变更分解为**扩展**、**迁移**、**收缩**三个顺序阶段的实践方法。其核心心智模型是将数据库变更视为一次需要逐步换舷的航行，确保在任何中间时刻，系统都能用当前已发布的任意版本代码与已执行的任意子集变更正常运行。

## 扩展阶段

扩展阶段是流程的起点，**只做加法**。此阶段的典型操作包括新增列、创建新表等。其核心原则是必须保证向后兼容，即数据库变更后，旧版本的代码仍能正常运行。

## 迁移阶段

迁移阶段进行**数据回填**，实现新旧数据结构的并存。数据回填有两种主要方式：
*   **批量回填**：适合数据量大、切换时间紧的场景。
*   **懒回填**：适合访问分散的场景。

在回滚策略上，遵循**回滚代码而非数据**的原则。因为数据回滚成本高且易导致数据漂移，已执行的数据回填不做反向回填。兼容性判断以旧代码为准。

## 收缩阶段

收缩阶段是流程的终点，也是**唯一危险的阶段**。此阶段在确认无人使用旧结构后才进行删除操作。安全执行收缩阶段需遵循以下步骤：
1.  先发布不再引用旧结构的代码版本。
2.  观察至少一个完整发布周期。
3.  依据监控指标（如旧结构访问计数）判断是否可安全删除。

## 阶段合并与简化

规范做法是不合并扩展和迁移阶段，因为三阶段拆开提供了决策点和纠错缓冲带。但对于简单变更（如带默认值的可空加列），可提供简化流程的快车道。
