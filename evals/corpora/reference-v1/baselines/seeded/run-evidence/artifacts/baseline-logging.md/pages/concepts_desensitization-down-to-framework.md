# 脱敏下沉

脱敏下沉是一种日志架构决策，其核心思想是将日志的可用性与合规性从依赖个人自觉转变为由机制和框架保证。它要求将脱敏逻辑下沉到日志框架层，通过字段名规则库和值模式进行统一掩码，从而确保敏感字段默认不落日志。

## 核心思想

该决策旨在解决日志敏感信息泄露问题。它不依赖于开发者在每个业务点手动处理脱敏，而是通过框架层面的统一机制来强制执行脱敏策略，从而将合规性从“人治”转变为“机治”。

## 实现机制

脱敏下沉的实现依赖于两个关键组件：

1.  **字段名规则库**：基于日志字段的名称（例如 `password`, `credit_card_number`）来识别敏感信息。由于业务字段命名要求稳定（字段名一旦写入存储即成为不可变的 schema），这为基于字段名的脱敏提供了可靠基础。
2.  **值模式掩码**：基于日志字段值的模式（例如正则表达式匹配手机号、身份证号格式）来识别并掩码敏感信息，作为字段名规则的补充。

## 在日志规范中的定位

脱敏下沉是结构化日志规范中针对脱敏问题的明确要求。它与其他规范共同构成了日志管理的完整体系：

*   **与日志分类的关系**：规范将日志分为[[entities/structured-logging-specification|排障日志、审计日志和指标事件]]。脱敏下沉主要应用于可能包含敏感信息的排障日志和审计日志。
*   **与字段规范的关系**：规范要求每条日志必须包含 `timestamp`、`level`、`service` 和 `request_id` 等基础字段。脱敏下沉机制在日志框架处理这些基础字段和业务字段时生效。
*   **与日志级别的关系**：规范强调 `ERROR` 级别日志全量保留。脱敏下沉确保即使在全量保留的 `ERROR` 日志中，敏感信息也已被处理。
