# 全局重试预算

全局重试预算是一种从宏观层面控制重试流量放大效应的机制。其核心目标是为系统内所有客户端或服务实例的重试行为设定一个总体的“配额”，防止在故障期间因大量客户端同时重试而导致对下游服务的请求量呈指数级增长，从而引发“重试风暴”。

## 核心目标

全局重试预算旨在解决重试机制带来的“别太多”问题。当多个客户端实例或服务同时对同一个故障的下游服务发起重试时，重试流量会与原始业务流量叠加，可能瞬间放大对下游的请求压力，甚至导致下游服务彻底崩溃。全局重试预算通过设定一个宏观的流量上限，确保重试行为不会超出下游服务的承载能力。

## 实现方向

根据现有设计，全局重试预算的实现方向主要包括：

- **实例级配额**：为每个客户端或服务实例分配一个独立的重试配额。每个实例在其配额内进行重试，超出配额后将停止重试，直接返回错误。
- **集群级配额**：为整个服务集群设定一个总的重试配额。所有实例共享此配额，当集群总重试次数达到上限后，所有实例都将停止重试。

## 在重试设计体系中的位置

全局重试预算与 [[concepts/retry-mechanism|重试机制]] 中的其他组件（如错误分类、指数退避、随机抖动）协同工作，共同构成一个完整的重试控制体系：

- **错误分类**：决定“该不该”重试。
- **指数退避与随机抖动**：控制“何时”以及“如何”重试，避免重试过于频繁或过于集中。
- **全局重试预算**：控制“总共能重试多少次”，是宏观层面的最终安全阀。

最终结论是，重试机制需要指数退避、随机抖动和全局预算三者齐备，才能在提升成功率的同时，有效控制对下游的放大效应。
