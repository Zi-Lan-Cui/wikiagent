# 幂等键

幂等键是业务侧为确保写操作可重复执行而引入的去重标识。它是解决“可重试≠可重复”问题的关键机制，是写操作安全重试的前提。

## 核心职责与边界

幂等键的核心职责是**业务侧去重**。它与[[concepts/retry-mechanism|重试机制]]的边界清晰：重试框架（基础设施侧）根据错误类型（如下游是否可能恢复）决定“该不该”重试；而幂等键（业务侧）则保障重试时操作的可重复性，即“重试了会不会出错”。

判断一个操作是否可重试，只看错误类型（例如连接失败、503、429等暂时性故障）。操作的可重复性则完全依赖幂等保障。因此，**写请求必须带幂等键**。

## 在重试流程中的作用

当一次写操作因暂时性故障（如超时）失败后，重试机制会发起重试。此时，幂等键确保下游服务能够识别这是一个重复请求，并返回与首次执行相同的结果，而不是重复执行业务逻辑（如再次扣减库存）。

对于没有幂等保障的写操作，超时后无论是重试还是报错，都没有免费的正确答案。正确的解法是补齐幂等能力。

## 与重试决策的关系

重试框架的决策逻辑（基于错误码）不应受到幂等键的影响。幂等键的存在，是为了让重试框架做出的“重试”决策能够安全执行。同时，如果下游服务已明确返回“请求已处理”，则不应继续重试，无论是否携带幂等键。

最终结论是：重试机制是错误中继站，而**去重责任在业务侧**，由幂等键承担。
