# 基于优先级的限流

## 概述

基于优先级的限流是针对传统无差别保护型限流缺陷的改进方向。其核心动机源于实际事故教训：无差别的保护型限流会误伤关键业务链路（如支付回调），因此需要在限流策略中引入流量优先级区分机制。

## 从保护型限流到优先级限流

当前网关实现的保护型限流采用无差别拒绝策略，旨在保护服务免于过载。然而，2026年8月的事故表明，这种策略存在缺陷：它无法区分流量的重要性，导致核心链路（如支付回调）在流量高峰时被误伤，影响关键业务功能。

因此，限流策略的演进方向之一是引入优先级区分。这意味着系统需要能够识别不同请求的优先级（例如，支付回调请求应高于普通查询请求），并在资源紧张时优先保障高优先级流量的通过，而对低优先级流量实施更严格的限流。

## 在限流策略演进中的位置

基于优先级的限流是限流策略层面的一个概念演进，它关注的是“如何更智能地分配限流资源”，而非限流器的具体实现技术（如令牌桶算法或基于Redis的分布式计数）。它与 [[entities/rate-limiter|限流器]] 的关系是：优先级限流是对现有限流器策略的增强和演进，旨在解决其策略层面的不足。

## 已知缺口

根据来源文档，当前实现中优先级分流缺乏一个统一的框架。这意味着如何定义优先级、如何在限流决策中应用优先级规则、以及不同优先级流量之间的具体隔离与保障机制，尚未形成标准化的设计。
