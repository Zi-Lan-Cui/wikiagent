# 限流器

订单网关与订单服务中用于保护服务免于过载并按契约分配资源配额的具体技术组件。当前实现为保护型限流，但基于事故教训，需区分流量优先级。

## 核心算法与参数

网关采用**令牌桶算法**进行限流。其关键参数**桶容量**决定了系统对突发流量的容忍度。参数设置需基于下游服务的真实容量。

## 分布式限流实现

分布式限流通过**Redis计数**实现全局速率上限。具体实现采用**窗口计数法**，并允许**10%的误差容忍**。为优化性能，采用**本地预扣**机制，将Redis的QPS降至请求量的**5%**。当Redis故障时，采取**fail-open**策略。

## 限流、熔断与重试的协作

限流器与熔断器、重试机制职责明确：
- **限流**：控制入口速率。
- **熔断**：判断下游状态。
- **重试**：处理单请求失败。

具体协作规则包括：
- 当下游返回429状态码时，上游应尊重 `Retry-After` 头进行减速。
- 被限流拒绝的请求**不应重试**。
- 限流触发后需返回**429状态码**与**Retry-After头**，并监控被拒流量的趋势。

## 已知缺口

当前实现存在以下已知缺口：
- 仅实现了**入口限流**，**出口限流**尚未实现，存在“集体超载”风险。
- **优先级分流**缺乏统一框架。
- **限流与重试预算尚未联动**。
