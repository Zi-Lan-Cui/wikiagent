# Redis分布式锁实现机制

本文档详细描述了基于Redis实现的分布式锁的具体工程机制，包括获取、释放、租约管理与续期逻辑。该实现是 [[concepts/distributed-lock-lease-contract|分布式锁租约契约模型]] 的具体执行层。

## 获取锁

获取锁通过原子命令实现，确保互斥性和租约设置：
```redis
SET lock:order:{order_id} {token} NX PX {ttl}
```
- `NX` 参数确保仅当键不存在时设置，实现互斥。
- `PX` 参数设置锁的过期时间（租约），单位为毫秒。
- `token` 是一个唯一值，用于后续释放锁时的身份校验。

## 释放锁

释放锁必须通过Lua脚本原子执行，以防止误删他人的锁。脚本在校验token匹配后才执行删除操作。

## 租约与续期

- **租约设置**：锁的TTL（租约时间）通常设置为任务p95耗时的两到三倍。
- **续期机制**：锁的持有者可以按固定周期续期，续期时必须校验token。
- **关键原则**：如果锁到期且续期未成功，进程必须立即停止操作，即使任务已执行一半。

## 已知缺陷与应对

文档通过事故复盘揭示了锁机制的固有缺陷：锁的过期判定依赖时间流逝，而进程可能因GC停顿等原因冻结，导致锁过期但进程仍认为自己持有锁。针对此问题，提出了引入fencing token的系统性解法，但当前尚未实现。

获取锁失败时，采用有界等待策略，避免无限阻塞。

## 设计原则与边界

- 分布式锁仅承诺互斥，不保证业务正确性，不能替代幂等设计。
- 锁内临界区应尽量短。
- 资金类操作需要锁、幂等、对账三层保障。
- 续期失败后，统一规则是转入“只收尾、不新增”模式，完成当前原子单元后停止，并将任务标记为pending-verify。
