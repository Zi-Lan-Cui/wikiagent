# 回滚代码而非数据

在数据库迁移实践中，当需要回滚时，应遵循一个核心原则：**只回滚代码版本，不回滚已执行的数据回填操作**。

## 原则内容

回滚操作应仅限于将应用代码回退到上一个已知稳定的版本。对于在迁移过程中已经执行的数据回填（例如，为新列填充数据），即使代码回滚，这些数据变更也**不做反向回填**。

## 原因

该原则基于两个关键考量：

1.  **数据回滚成本高**：反向回填或删除已写入的数据，其操作成本和风险通常远高于代码部署。
2.  **易导致数据漂移**：试图撤销数据变更可能引入数据不一致或丢失，导致难以追踪和修复的“数据漂移”问题。

## 与迁移流程的关系

此原则与[[entities/three-phase-migration-process|三阶段迁移流程]]形成一种张力。流程要求分阶段执行变更，而回滚原则则规定了在流程中遇到问题时的退出策略。它强调，即使代码回滚，已执行的数据迁移步骤（如数据回填）应被视为既成事实，系统需要设计为能够兼容这种状态。

兼容性判断以旧代码为准，确保数据库变更后，旧版本的代码仍能正常运行。
